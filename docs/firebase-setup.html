Firebase(FCM) 설정 가이드

Firebase를 처음 써도 따라 할 수 있게, 콘솔의 어느 메뉴에서 무엇을 받아 어느 파일·어느 환경변수에 넣는지까지 적었다. 소요 시간 약 20분, 비용 0원.

이 프로젝트에서 Firebase가 하는 일

이 저장소는 Firebase를 딱 한 가지에만 쓴다. Android 앱이 꺼져 있어도 낙상 알림을 받게 하는 것이다. 로그인, 데이터베이스, 파일 저장, 애널리틱스는 전혀 쓰지 않는다.

그러려면 서로 다른 두 개의 파일이 필요하다. 하나는 앱에, 하나는 서버에 들어간다. 이 둘을 헷갈리는 게 초보자가 가장 많이 하는 실수라서 먼저 못 박고 간다.

① google-services.json앱에 넣는다
"이 앱은 내 Firebase 프로젝트 소속"이라는 신분증. 비밀이 아니다.
app/android/app/에 파일로 둔다.
② 서비스 계정 JSON서버에 넣는다
"이 서버가 알림을 보내도 된다"는 인감도장. 비밀키다.
Render 환경변수 FIREBASE_SERVICE_ACCOUNT에 넣는다.
흐름동작 순서
앱이 ①로 FCM 토큰을 받아 서버에 등록 → 낙상 발생 → 서버가 ②로 서명해 FCM에 발송 → 폰에 알림.

지금 이 저장소의 상태

필요한 것현재안 하면 벌어지는 일
app/android/app/google-services.json 없음 Android 빌드가 실패한다. app/android/app/build.gradle.kts가 google-services 플러그인을 무조건 적용하는데, 이 플러그인은 파일이 없으면 빌드를 멈춘다.
Render 환경변수 FIREBASE_SERVICE_ACCOUNT 비어 있음 서버가 FCM 채널을 조용히 끈다(backend/falls/push.py). 에러는 안 나고 알림만 안 온다.
둘 중 하나만 해도 알림은 안 온다. ①만 하면 앱은 빌드되고 토큰도 등록되지만 서버가 발송을 못 한다. ②만 하면 서버는 준비됐지만 앱이 토큰을 못 만든다. 반드시 둘 다 해야 한다.

먼저 확인 — Android SDK

1~4단계(콘솔 발급과 서버 설정)는 지금 바로 할 수 있지만, 5단계에서 앱을 빌드하려면 Android SDK가 필요하다. 지금 상태를 먼저 본다.

flutter doctor
이 맥에는 아직 Android SDK가 없다. 2026-07-24 기준 flutter doctor 결과가 [✗] Android toolchain — Unable to locate Android SDK다. 이 프로젝트는 지금까지 iOS로만 빌드해 왔기 때문이다.
Android 앱을 빌드하려면 Android Studio를 설치하고 첫 실행 마법사에서 SDK를 받은 뒤, flutter doctor --android-licenses로 라이선스에 동의해야 한다. flutter doctor의 Android 항목이 [✓]가 되면 준비 끝이다.
설치가 부담되면 1~4단계만 먼저 해 두어도 손해가 없다. 나중에 SDK를 깔고 5단계만 이어서 하면 된다.
요금 걱정은 없다. FCM(클라우드 메시징)은 Firebase 무료 플랜(Spark)에서 발송량 제한 없이 무료다. 신용카드를 등록하라는 화면이 나오면 잘못 들어간 것이니 뒤로 가면 된다.

1Firebase 프로젝트 만들기

  1. console.firebase.google.com에 접속해 구글 계정으로 로그인한다.
  2. 프로젝트 만들기(또는 프로젝트 추가)를 누른다.
  3. 프로젝트 이름을 입력한다. 자유지만 fall-guardian처럼 알아볼 수 있게 짓는다. 아래에 fall-guardian-3f2a1 같은 프로젝트 ID가 자동으로 붙는데, 그게 실제 식별자다. 이름과 다르다고 놀라지 않아도 된다.
  4. Google 애널리틱스는 끈다. 토글을 꺼도 프로젝트 생성에 아무 문제가 없고, 이 프로젝트는 애널리틱스를 쓰지 않는다.
  5. 프로젝트 만들기 → 30초쯤 기다리면 대시보드로 들어간다.
여기까지의 확인. 왼쪽 위에 방금 만든 프로젝트 이름이 보이고, 가운데에 iOS·Android·웹 아이콘 세 개가 있는 "시작하려면 앱을 추가하세요" 화면이 뜨면 정상이다.

2Android 앱 등록하고 google-services.json 넣기

2-1. 콘솔에서 앱 등록

  1. 프로젝트 개요 화면 가운데의 Android 아이콘을 누른다. (이미 앱을 추가한 적이 있다면 왼쪽 위 톱니 → 프로젝트 설정 → 아래 앱 추가 → Android)
  2. Android 패키지 이름에 아래를 글자 하나 틀리지 않게 입력한다. 
    com.example.fall_guardian

    이 값은 지어내는 게 아니라 이미 코드에 정해져 있는 값이다. 직접 확인하려면 app/android/app/build.gradle.kts의 applicationId 줄을 보면 된다. 오타가 나면 나중에 앱이 Firebase를 못 찾는다.

  3. 앱 닉네임은 선택이다. 비워도 되고 낙상 앱처럼 아무거나 넣어도 된다.
  4. 디버그 서명 인증서 SHA-1은 비워 둔다. 구글 로그인·Dynamic Links에만 필요하고 FCM에는 필요 없다.
  5. 앱 등록을 누른다.

2-2. 파일 내려받아 정확한 위치에 두기

  1. 다음 화면에서 google-services.json 다운로드를 누른다. 보통 ~/Downloads에 저장된다.
  2. 그 뒤에 나오는 3단계·4단계(Gradle 설정 추가) 화면은 그냥 넘긴다. 이 저장소에는 이미 다 되어 있다.
    • app/android/settings.gradle.kts — 플러그인 선언 완료
    • app/android/app/build.gradle.kts — 플러그인 적용 완료
    • app/pubspec.yaml — firebase_core, firebase_messaging 추가 완료
    "다음" → "콘솔로 이동"을 계속 눌러 빠져나오면 된다.
  3. 내려받은 파일을 아래 경로로 옮긴다. 터미널에서 한 줄이면 된다.
mv ~/Downloads/google-services.json /Users/munhokang/82107/weniv_project/app/android/app/
경로를 한 칸 틀리는 실수가 제일 흔하다. app/android/app/google-services.json 이 맞다.
app/android/(app 폴더 하나 빠짐)이나 app/에 두면 빌드가 "google-services.json is missing"으로 실패한다.

제자리에 갔는지 확인한다.

ls -l /Users/munhokang/82107/weniv_project/app/android/app/google-services.json

파일 내용에 패키지 이름이 제대로 들어갔는지도 한 번 본다. com.example.fall_guardian이 나와야 한다.

grep package_name /Users/munhokang/82107/weniv_project/app/android/app/google-services.json

2-3. 빌드로 검증

Android SDK가 아직 없다면(0단계 참고) 이 검증은 건너뛰고 3단계로 간다. 대신 위 grep으로 패키지 이름만이라도 눈으로 확인해 둔다.

cd /Users/munhokang/82107/weniv_project/app
flutter clean
flutter pub get
flutter build apk --debug
여기까지의 확인. ✓ Built build/app/outputs/flutter-apk/app-debug.apk가 나오면 ①번 파일은 끝이다. 이 빌드가 성공했다는 건 파일 위치와 패키지 이름이 둘 다 맞다는 뜻이라, 이 단계에서 검증하고 넘어가는 게 나중에 시간을 아낀다.

2-4. 이 파일, git에 커밋해도 되나?

커밋해도 된다. google-services.json은 비밀키가 아니라 공개 식별자다. 안에 든 API 키는 Android 앱 패키지에 묶여 있어 남이 가져가도 남의 앱에서는 동작하지 않는다. 실제로 안드로이드 앱을 뜯으면 누구나 볼 수 있는 값이다.

다만 저장소가 Public이고 "내 Firebase 프로젝트 ID를 굳이 노출하고 싶지 않다"면 무시 목록에 넣어도 된다. 대신 다른 컴퓨터에서 빌드할 때마다 이 파일을 다시 받아 넣어야 한다.

# 선택 사항 — 커밋하지 않기로 했다면
echo "app/android/app/google-services.json" >> /Users/munhokang/82107/weniv_project/.gitignore

3서버용 서비스 계정 비공개 키 발급

여기서 받는 파일은 ①번과 완전히 다른 것이다. 이건 진짜 비밀키다.

  1. Firebase 콘솔 왼쪽 위 톱니바퀴 → 프로젝트 설정.
  2. 상단 탭에서 서비스 계정을 누른다.
  3. Firebase Admin SDK 섹션 아래의 새 비공개 키 생성 버튼을 누른다.
  4. 경고 팝업이 뜬다. "이 키에 대한 액세스 권한을 안전하게 보관하세요"라는 내용이다. 키 생성을 누른다.
  5. fall-guardian-3f2a1-firebase-adminsdk-xxxxx.json 같은 이름의 파일이 자동으로 다운로드된다.
이 파일은 절대 커밋하지 않는다. 이 JSON 하나면 누구든 내 Firebase 프로젝트 이름으로 알림을 보낼 수 있다. GitHub에 올라가면 봇이 몇 분 안에 긁어간다.
바탕화면이나 다운로드 폴더에 두고, 4단계가 끝나면 지워도 된다(필요하면 콘솔에서 새로 발급하면 그만이다).
이 저장소 폴더 안에 복사해 두지 않는 게 가장 안전하다.

3-1. 클라우드 메시징 API가 켜져 있는지 확인 (보통 자동)

같은 프로젝트 설정 화면에서 클라우드 메시징 탭으로 간다. Firebase 클라우드 메시징 API (V1)가 사용 설정됨이면 된다. 요즘 만든 프로젝트는 기본으로 켜져 있다. 아래에 있는 "Cloud Messaging API (기존)"은 지원 종료된 옛 방식이라 켜지 않아도 된다.

4Render 환경변수에 넣기

서버는 이 JSON을 파일이 아니라 환경변수 문자열로 읽는다(backend/config/settings.py의 FIREBASE_SERVICE_ACCOUNT). 그래서 줄바꿈 없는 한 줄로 바꿔야 한다.

4-1. 한 줄로 변환

다운로드한 파일 이름을 본인 것으로 바꿔서 실행한다.

python3 -c "import json,sys; print(json.dumps(json.load(open(sys.argv[1]))))" \
  ~/Downloads/fall-guardian-3f2a1-firebase-adminsdk-xxxxx.json

macOS라면 화면에 안 뿌리고 바로 클립보드로 넣는 편이 안전하다.

python3 -c "import json,sys; print(json.dumps(json.load(open(sys.argv[1]))))" \
  ~/Downloads/받은파일.json | pbcopy
메모장으로 열어서 손으로 복사하지 않는다. 안의 private_key 값에는 \n이 잔뜩 들어 있는데, 편집기로 옮기다 보면 실제 줄바꿈으로 바뀌거나 잘려서 서버에서 "Could not deserialize key data" 에러가 난다. 반드시 위 명령으로 변환한다.

4-2. Render 대시보드에 붙여넣기

  1. dashboard.render.com 접속 → 서비스 목록에서 fall-backend 클릭.
  2. 왼쪽 메뉴에서 Environment를 누른다.
  3. FIREBASE_SERVICE_ACCOUNT 항목을 찾는다. render.yaml에 sync: false로 선언돼 있어서 이름은 이미 있고 값만 비어 있다. 없으면 Add Environment Variable로 이름을 정확히 그대로 추가한다.
  4. 값 칸에 4-1에서 복사한 한 줄을 붙여넣는다. 앞뒤에 따옴표를 추가로 붙이지 않는다. {로 시작해 }로 끝나면 맞다.
  5. Save Changes. 저장하면 Render가 자동으로 재배포한다. 2~4분 기다린다.
여기까지의 확인. Render의 Logs 탭에서 마지막 배포가 Live가 되고, 브라우저로 백엔드 주소를 열었을 때 {"status": "ok", ...}가 보이면 된다.

5실제로 알림이 오는지 확인

세 단계로 나눠서 확인한다. 중간에 끊기면 어디가 문제인지 바로 알 수 있다.

5-1. 앱이 토큰을 받아 서버에 등록했는가

Android 기기를 USB로 연결하고 실행한다.

cd /Users/munhokang/82107/weniv_project/app
flutter run --release

앱에서 로그인한다. 로그인 직후 Push.register()가 돈다(app/lib/push.dart). 알림 권한을 물으면 허용한다.

터미널 로그에 아래 문구가 안 보이면 성공이다.

FCM 등록 실패 — 폴링만으로 동작한다. ...

이 메시지가 보이면 뒤에 붙은 원인을 읽는다. 이 앱은 푸시가 실패해도 절대 죽지 않고 폴링으로 넘어가게 만들어져 있어서, 화면에 아무 에러도 안 뜨는 채로 조용히 실패할 수 있다. 그래서 로그를 봐야 한다.

5-2. 서버에 기기가 등록됐는가

브라우저로 <백엔드주소>/ansgh/에 관리자 계정으로 접속해 Push devices 목록을 본다. kind=fcm인 행이 방금 로그인한 계정으로 하나 있으면 5-1이 진짜로 성공한 것이다.

5-3. 백그라운드 알림이 오는가

앱을 완전히 백그라운드로 보내고(홈 버튼) 화면을 끈 다음, 터미널에서 낙상 이벤트를 하나 만든다. 먼저 토큰을 받는다.

curl -X POST https://fall-backend-l3pg.onrender.com/api/auth/login/ \
  -H 'Content-Type: application/json' \
  -d '{"username":"보호자계정","password":"비밀번호"}'

응답의 token 값을 넣어 낙상을 등록한다.

curl -X POST https://fall-backend-l3pg.onrender.com/api/falls/ \
  -H "Authorization: Token 받은토큰" \
  -H 'Content-Type: application/json' \
  -d '{"room_name":"안방","room_number":1,"occurred_at":"2026-07-24T12:00:00Z","confidence":0.9}'
성공이면 몇 초 안에 잠금 화면에 "낙상 감지 — 안방 1에서 낙상 감지"가 뜬다. 여기까지 오면 설정 끝이다.
같은 명령을 두 번 보내면 400이 난다. (guardian, room_name, room_number, occurred_at)에 중복 방지 제약이 걸려 있다(backend/falls/models.py). 다시 테스트할 때는 occurred_at의 시각을 바꾸면 된다.

서비스 계정 JSON
*-firebase-adminsdk-*.json		 그렇다 저장소 안에 두지 않는다. 슬랙·메일·이슈에 붙여넣지 않는다. Render 환경변수에만 넣는다.

실수로 서비스 계정 키를 커밋했다면, 파일을 지우는 것만으로는 부족하다(git 히스토리에 남는다). Firebase 콘솔 → 프로젝트 설정 → 서비스 계정 → Google Cloud 서비스 계정 관리에서 해당 키를 삭제하고 새로 발급한 뒤 Render 환경변수를 교체한다.

문제 해결

증상원인과 해결
빌드 에러
File google-services.json is missing		 파일 위치가 틀렸다. app/android/app/ 바로 아래여야 한다. ls app/android/app/google-services.json으로 확인한다.
빌드 에러
No matching client found for package name 'com.example.fall_guardian'		 Firebase 콘솔에 등록한 패키지 이름에 오타가 있다. 콘솔 → 프로젝트 설정 → 내 앱에서 확인하고, 틀렸으면 Android 앱을 하나 더 추가해 정확한 이름으로 등록한 뒤 json을 다시 받는다(기존 앱은 지워도 되고 둬도 된다).
앱 로그에 FCM 등록 실패가 뜬다 뒤에 붙은 원인을 읽는다. SERVICE_NOT_AVAILABLE이면 네트워크·Google Play 서비스 문제라 잠시 뒤 재시도. 401이면 앱이 로그인 상태가 아니다.
앱은 정상인데 알림이 안 온다 서버 쪽 ②번이 빠졌다. Render → Environment에서 FIREBASE_SERVICE_ACCOUNT 값이 채워져 있는지, 저장 후 재배포가 Live가 됐는지 확인한다.
Render 로그에
Could not deserialize key data 또는 JSON 파싱 에러		 한 줄 변환을 안 했거나 값이 잘렸다. 4-1의 python3 -c ... 명령으로 다시 변환해 통째로 교체한다.
Render 로그에
FCM 발송 실패 (device=N)		 서비스 계정이 다른 Firebase 프로젝트 것이다. ①과 ②는 같은 프로젝트에서 나와야 한다. 콘솔에서 프로젝트를 갈아탄 채 키를 받지 않았는지 확인한다.
앱이 켜져 있을 때만 알림이 오고, 꺼두면 안 온다 FCM이 아니라 폴링으로 동작 중이라는 신호다. 5-2의 Push devices 목록에 kind=fcm 행이 있는지부터 확인한다. 있는데도 그렇다면 폰 설정 → 앱 → 배터리에서 제한 없음으로 바꾼다(제조사 절전 기능이 백그라운드 수신을 막는 경우가 흔하다).
알림이 아예 안 뜬다(Android 13 이상) 알림 권한을 거부했다. 폰 설정 → 앱 → fall_guardian → 알림에서 켠다.
아이폰에서 알림이 안 온다 정상이다. iOS 네이티브 앱은 폴링만 쓴다. 아이폰에서 백그라운드 알림을 받으려면 보호자 페이지(guardian.html)를 홈 화면에 추가한 PWA를 쓴다 — 이건 Firebase가 아니라 VAPID 설정이다.
로그아웃했는데 알림이 계속 온다 로그아웃 시 Push.unregister()가 토큰을 지우는데 네트워크 실패로 못 지웠을 수 있다. /ansgh/의 Push devices에서 해당 행을 직접 삭제한다.

완료 체크리스트

  • Firebase 프로젝트를 만들었다(애널리틱스는 껐다)
  • 패키지 이름 com.example.fall_guardian으로 Android 앱을 등록했다
  • google-services.json을 app/android/app/에 넣었다
  • flutter build apk --debug가 성공한다
  • 서비스 계정 비공개 키 JSON을 받았고, 저장소 밖에 두었다
  • 한 줄로 변환해 Render의 FIREBASE_SERVICE_ACCOUNT에 넣었고 재배포가 끝났다
  • 앱 로그인 후 /ansgh/의 Push devices에 kind=fcm 행이 보인다
  • 앱을 끈 상태에서 curl로 낙상을 등록했더니 잠금 화면에 알림이 왔다
