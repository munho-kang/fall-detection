낙상 감지 시스템 — 배포 가이드

프론트는 GitHub Pages, 백엔드는 Render, 앱은 내 아이폰. 위에서 아래로 순서대로 따라 하면 된다.

web/ 감지 페이지GitHub Pages
어르신 방의 카메라 브라우저. 영상은 브라우저 밖으로 안 나간다.
backend/ Django APIRender + Postgres
낙상 기록 저장, 계정·토큰 관리.
app/ Flutter 앱보호자 아이폰
5초 폴링으로 새 낙상을 알림으로 띄운다.
왜 이 순서인가. Render 주소는 배포해 봐야 알 수 있다(뒤에 랜덤 문자가 붙는다). 그래서 백엔드를 먼저 올리고 → 그 주소를 코드에 적고 → 다시 push하는 흐름이 필요하다. 전부 무료 플랜이고 카드 등록도 필요 없다.

바로가기 — 1. GitHub에 올리기 · 2. Render 백엔드 · 3. 주소 반영 · 4. 감지 페이지 확인 · 5. 아이폰 설치 · 운영 주의 · 문제 해결

1GitHub 저장소 만들고 올리기 (프론트 배포)

  1. github.com → 우측 상단 + → New repository. 이름은 자유(예: fall-detection). 반드시 Public으로 만든다 — 무료 계정의 Pages는 공개 저장소에서만 동작한다. "Add a README" 같은 체크박스는 전부 끈다.
  2. 터미널에서 원격을 연결하고 push한다. <아이디>와 <저장소>는 본인 것으로 바꾼다.
cd /Users/munhokang/82107/weniv_project
git remote add origin https://github.com/<아이디>/<저장소>.git
git push -u origin main

push 중 인증 창이 뜨면 GitHub 계정으로 로그인한다(브라우저 인증 또는 Personal Access Token).

Pages 켜기 — 두 방법 중 하나

방법 A — 권장방법 B — 브랜치 배포
설정 Settings → Pages → Source를 GitHub Actions로 선택 Settings → Pages → Branch를 main으로 선택 후 Save
동작 저장소의 워크플로가 web/ 폴더만 사이트로 올린다. URL을 열면 바로 로그인 화면이 뜬다. 저장소 전체가 사이트가 된다. 루트의 index.html이 web/으로 자동 이동시켜 준다(주소가 한 번 바뀐다).
반영 시점 push 직후 Actions 탭에서 진행 확인 가능 Save 후 1~2분 내 자동 빌드
방법 A에서 첫 워크플로가 빨간색(실패)이어도 괜찮다. Source를 설정하기 전에 push가 먼저 실행됐기 때문이다. 3단계에서 다시 push하면 자동으로 재실행되어 성공한다. 기다리기 싫으면 Actions 탭 → 실패한 실행 → Re-run all jobs.

사이트 주소는 두 방법 모두 https://<아이디>.github.io/<저장소>/다.

2Render에 백엔드 배포

  1. render.com 가입(GitHub 계정으로 가입하면 저장소 연동이 바로 된다).
  2. 대시보드 → New + → Blueprint → 방금 만든 저장소 선택. 루트의 render.yaml을 자동으로 읽어 웹 서비스(fall-backend) + 무료 Postgres(fall-db)를 함께 만든다.
  3. 환경변수 입력 화면에서 아래 4개를 채우고 Apply.
키넣을 값
CORS_ALLOWED_ORIGINShttps://<아이디>.github.io — 끝에 / 없이, 저장소 이름 없이. 감지 페이지의 요청을 허용하는 값이다.
DJANGO_SUPERUSER_USERNAME관리자 아이디. /ansgh/ 접속용이다.
DJANGO_SUPERUSER_EMAIL이메일(형식만 맞으면 된다).
DJANGO_SUPERUSER_PASSWORD관리자 비밀번호 — 길고 어렵게.
  1. 첫 빌드는 5~10분 걸린다. 끝나면 fall-backend 서비스 페이지 상단의 URL을 복사한다. 예: https://fall-backend-a1b2.onrender.com
  2. 확인 두 가지.
    • 브라우저에서 그 URL을 열면 {"status": "ok", ...}가 보인다.
    • <URL>/ansgh/에서 방금 만든 관리자 계정으로 로그인이 된다. (기본 /admin/ 경로는 열리지 않는다 — 404가 정상이다.)
계정 구조. 위 관리자 계정은 관리 화면용이다. 실제 보호자 계정은 감지 페이지나 앱의 회원가입으로 만든다. 웹(감지 페이지)과 폰 앱은 같은 계정으로 로그인해야 알림이 이어진다.

3배포 주소를 코드에 반영

복사해 둔 Render 주소로 두 파일의 XXXX 자리 표시자를 바꾼다.

파일바꿀 상수
web/js/api.jsPROD_API_BASE
app/lib/api.dart_prodBaseUrl
git add web/js/api.js app/lib/api.dart
git commit -m "배포된 Render 주소 반영"
git push

이 push로 감지 페이지가 새 주소를 들고 자동 재배포된다(방법 A 기준. 방법 B도 1~2분 내 반영).

4감지 페이지 동작 확인

  1. https://<아이디>.github.io/<저장소>/ 접속 → 로그인 화면이 뜬다.
  2. 회원가입으로 보호자 계정을 만든다(가입하면 바로 로그인된다). 비밀번호는 8자 이상, 숫자만은 불가.
  3. 방 선택 → 감지 시작 → 카메라 허용. 검은 화면 위에 스켈레톤이 그려지면 정상이다.
첫 로그인이 1분쯤 걸릴 수 있다. 무료 플랜 백엔드는 15분간 요청이 없으면 잠든다. 잠든 직후의 첫 요청은 서버가 깨어나는 시간만큼 느리다. 실패처럼 보여도 잠시 뒤 다시 시도하면 된다.

5아이폰에 앱 설치

  1. 아이폰을 Mac에 USB로 연결한다(이전에 무선 디버깅을 켜뒀다면 같은 Wi‑Fi로도 잡힌다).
  2. 릴리즈 모드로 설치한다. 릴리즈 빌드는 자동으로 Render 백엔드를 바라보므로 따로 설정할 게 없다.
cd /Users/munhokang/82107/weniv_project/app
flutter devices                      # 아이폰이 목록에 보이는지 확인
flutter run --release -d <기기 이름>
  1. 처음 설치라면 폰에서 설정 → 일반 → VPN 및 기기 관리 → 개발자 앱 신뢰.
  2. 앱에서 4단계와 같은 계정으로 로그인(앱에서도 회원가입 가능). 낙상 목록이 보이면 완료.
  3. 감지 페이지 쪽에서 낙상이 확정되면 5초 폴링 안에 폰 알림이 온다. 설치가 끝나면 케이블은 뽑아도 된다.
무료 Apple ID 서명은 7일 뒤 만료된다. 앱이 안 열리게 되면 위 flutter run --release를 다시 실행하면 된다. Apple Developer Program($99/년) 가입 시 1년짜리 서명이 된다.

운영할 때 알아둘 것

  • 알림은 앱이 화면에 떠 있을 때만 온다. 폴링 구조라 백그라운드로 가면 멈춘다. 보호자 폰은 앱을 켠 채 두는 운용을 권장한다(전원 연결 + 자동 잠금 끔).
  • 앱이 떠 있는 동안 백엔드는 잠들지 않는다. 5초마다 폴링이 가기 때문이다. 반대로 아무도 안 보면 잠들고, 다음 첫 요청이 느리다.
  • 무료 Postgres는 생성 30일 뒤 만료된다. Render가 만료 전 메일을 보낸다. 계속 쓰려면 유료 전환하거나, Neon 무료 Postgres를 만들어 Render 환경변수 DATABASE_URL만 교체한다. 교체 후 재배포되면 테이블과 관리자 계정은 자동으로 다시 만들어진다(과거 낙상 기록은 옮기지 않으면 사라진다).
  • 카메라를 옮기면 재검수. 넘어지기 hipV 피크 0.5 이상, 눕기 tilt 60° 이상, 천천히 눕기 hipV 0.3 미만 — 세 기준을 다시 통과시켜야 한다(README 참고).

문제 해결

증상원인과 해결
로그인이 한참 걸리거나 실패무료 플랜 콜드스타트. 1분 뒤 재시도.
브라우저 콘솔에 CORS 에러Render 환경변수 CORS_ALLOWED_ORIGINS 확인 — https://<아이디>.github.io 정확히. 끝 / 금지, 저장소 이름 금지. 고친 뒤 자동 재배포를 기다렸다가 재시도.
Pages URL이 404방법 A면 Actions 탭 최근 실행이 성공인지, 방법 B면 Branch가 main으로 저장됐는지 확인. 설정 직후라면 1~2분 대기.
Pages URL에서 README나 문서가 보임방법 B에서 루트 리다이렉트가 아직 반영 전이다. 강력 새로고침(Cmd+Shift+R) 또는 /web/을 주소 뒤에 붙여 접속.
Render 빌드가 Python 버전에서 실패render.yaml의 PYTHON_VERSION을 3.13.4로 낮춰 커밋·push.
앱에서 로그인 실패api.dart의 XXXX를 실제 주소로 바꿨는지, --release로 빌드했는지 확인.
폰에 알림이 안 옴앱이 화면에 떠 있는지, iOS 알림 권한을 허용했는지, 웹과 같은 계정인지 확인.
admin 화면이 깨져 보임배포 직후 캐시 문제. 강력 새로고침(Cmd+Shift+R).
