낙상 감지 시스템 — 백엔드 구현 설명

감지 클라이언트가 낙상 이벤트를 보내면 저장하고, 보호자 앱이 자기 이벤트만 조회·확인하는 최소한의 Django REST API.

한 줄 요약. Django 6.0 + Django REST Framework 기반 REST 서버. 인증은 DRF 토큰, DB는 로컬 SQLite / 배포 Postgres 자동 전환, 배포는 Render에서 gunicorn + whitenoise. 앱은 딱 둘 — config(설정)와 falls(도메인). 실질 로직은 전부 falls에 있다.

바로가기 — 스택 · 1. 모델 · 2. 인증 · 3. 엔드포인트 · 4. 뷰 로직 · 5. 시리얼라이저 · 6. 환경 분기 · 7. 배포 · 8. 테스트

전체 그림

web/ 감지 페이지감지 클라이언트
낙상을 판정하면 이벤트를 POST한다.

1데이터 모델 — FallEvent 단 하나

falls/models.py의 FallEvent가 이 백엔드의 유일한 모델이다. 낙상 이벤트 1건을 표현하며, 방 정보를 별도 테이블로 정규화하지 않고 이벤트에 직접 들고 있다(단순함 우선).

필드의미
guardian이 이벤트를 소유한 보호자 (Django 기본 User에 FK, CASCADE)
room_name방 이름 — 안방·부엌·거실·화장실로 choices 제한
room_number방 번호 (양의 정수)
occurred_at클라이언트가 판정한 낙상 시각 (FALLING 진입 시각)
created_at서버 저장 시각 (auto_now_add)
confidence판정 시점 랜드마크 4개의 visibility 평균 (감지 신뢰도)
acknowledged_at보호자가 알림을 확인한 시각 (미확인이면 null)
정렬은 최신순으로 못박아 둔다. Meta.ordering = ["-id"] 덕분에 목록 API가 별도 정렬 없이도 최신 이벤트부터 내려준다.

2인증 — 토큰 기반, 기본은 전부 로그인 필수

settings.py에서 DRF 전역 기본값을 잡아둔다. 그래서 개별 뷰는 별도 설정 없이도 인증이 강제되고, 열어줘야 하는 곳만 예외 처리한다.

REST_FRAMEWORK = {
    "DEFAULT_AUTHENTICATION_CLASSES": [
        "rest_framework.authentication.TokenAuthentication",
    ],
    "DEFAULT_PERMISSION_CLASSES": [
        "rest_framework.permissions.IsAuthenticated",  # 기본이 로그인 필수
    ],
}
  • 클라이언트는 Authorization: Token <키> 헤더로 요청한다.
  • 회원가입처럼 열어야 하는 뷰만 @permission_classes([AllowAny])로 예외.
  • 토큰은 rest_framework.authtoken(DB 저장형)을 쓴다.

3API 엔드포인트

라우팅은 config/urls.py → falls/urls.py 순으로 연결된다. 요청 흐름은 다음과 같다.

감지 클라이언트낙상 판정
→
POST /api/falls/이벤트 저장 (guardian=요청자)
→
GET /api/falls/앱이 폴링 조회
→
POST …/acknowledge/보호자 확인

루트 / — config/urls.py

  • GET/ — {"status":"ok", ...} 헬스체크. Render 헬스체크 겸 "배포 살아있나" 육안 확인용.
  • admin은 기본 /admin/이 아니라 /ansgh/로 숨겨 자동 스캐너를 피한다.

/api/ 하위 — falls/urls.py

메서드 · 경로뷰설명
POST/api/auth/login/DRF obtain_auth_token아이디·비번 → 토큰 발급
POST/api/auth/signup/views.signup회원가입 후 즉시 토큰까지 발급
GET/api/falls/FallEventListCreate내 이벤트 목록 조회 (최신순)
POST/api/falls/낙상 이벤트 등록
POST/api/falls/<pk>/acknowledge/views.acknowledge알림 확인 처리 (멱등)

4뷰 로직 — 소유권과 멱등성

코드는 짧지만 보안 설계가 촘촘하다. 세 가지 패턴이 반복된다.

(a) 남의 데이터 격리 — 항상 요청자로 필터링

목록은 물론, acknowledge도 guardian까지 걸어 조회하므로 남의 이벤트는 존재 자체가 드러나지 않고 404가 된다.

class FallEventListCreate(generics.ListCreateAPIView):
    serializer_class = FallEventSerializer

    def get_queryset(self):
        # 남의 이벤트가 절대 새어나가지 않도록 요청자로 필터링한다
        return FallEvent.objects.filter(guardian=self.request.user)

(b) guardian 위조 방지 — 서버가 소유자를 강제

POST로 이벤트를 만들 때 클라이언트가 보낸 guardian 값을 무시하고 서버가 요청자로 못박는다. 게다가 시리얼라이저 fields에 guardian이 아예 없어 클라이언트가 건드릴 수 없다.

    def perform_create(self, serializer):
        serializer.save(guardian=self.request.user)

(c) acknowledge 멱등성 — 첫 확인 시각 보존

이미 확인된 이벤트를 다시 호출해도 최초 확인 시각을 덮어쓰지 않는다.

@api_view(["POST"])
@permission_classes([IsAuthenticated])
def acknowledge(request, pk):
    try:
        event = FallEvent.objects.get(pk=pk, guardian=request.user)
    except FallEvent.DoesNotExist:
        return Response({"detail": "Not found."}, status=404)

    if event.acknowledged_at is None:  # 첫 확인 시각을 보존한다
        event.acknowledged_at = timezone.now()
        event.save(update_fields=["acknowledged_at"])

    return Response(FallEventSerializer(event).data)

5시리얼라이저 — 비밀번호·소유권 안전장치

falls/serializers.py에 둘이 있다.

시리얼라이저역할
SignupSerializer password를 write_only로 막아 응답에 노출 금지. create_user()로 해시 저장(기본 create()는 평문이라 위험). settings의 비밀번호 규칙(8자 미만·흔한 비번·숫자만 금지)을 가입에도 적용.
FallEventSerializer id · created_at · acknowledged_at은 읽기 전용. guardian 필드를 아예 제외해 클라이언트가 소유자를 바꿀 수 없게 함.
왜 create_user인가. 기본 create()는 비밀번호를 평문으로 저장한다. User.objects.create_user(**data)가 해시해서 저장하므로 반드시 이쪽을 쓴다.

6환경 분기 — 로컬 vs Render

settings.py가 RENDER 환경변수 유무로 두 모드를 자동 전환한다.

로컬 개발Render 배포
DEBUGTrueFalse
DBSQLite (db.sqlite3)Postgres (DATABASE_URL)
ALLOWED_HOSTS['*']Render 도메인만
쿠키평문Secure + CSRF/프록시 SSL 헤더
배포 DB는 반드시 외부 Postgres. Render 무료 웹서비스의 디스크는 재배포·슬립마다 초기화된다. SQLite를 그대로 쓰면 보호자 계정과 낙상 기록이 전부 사라지므로, dj-database-url로 Postgres에 붙인다.

CORS. 감지 페이지는 다른 오리진(로컬 Live Server :5500, 배포 시 GitHub Pages)에서 뜬다. 배포 오리진은 CORS_ALLOWED_ORIGINS 환경변수(쉼표 구분)로 주입한다.

7배포 파이프라인

render.yaml 블루프린트로 웹 서비스 + 무료 Postgres를 한 번에 생성한다.

  • 빌드 — build.sh → pip install + collectstatic
  • 시작 — migrate → createsuperuser --noinput(보호자 계정 자동 생성) → gunicorn config.wsgi
  • SECRET_KEY는 Render가 자동 생성, 슈퍼유저 계정은 환경변수로 주입.
startCommand: python manage.py migrate --noinput \
  && (python manage.py createsuperuser --noinput || true) \
  && gunicorn config.wsgi:application

8테스트

falls/tests.py가 pytest로 백엔드의 보안·불변식을 고정한다. 위에서 설명한 설계 의도가 그대로 테스트로 남아 있다.

  • 익명 접근은 401
  • 목록에서 남의 이벤트 제외, 그리고 최신순 정렬
  • POST 시 guardian 위조는 무시되고 요청자로 강제
  • 남의 이벤트 acknowledge는 404
  • acknowledge 멱등성(두 번째 호출이 시각을 덮어쓰지 않음)
  • 회원가입 → 발급 토큰으로 즉시 로그인 가능
  • 중복 아이디 / 약한 비번은 400
마무리. 모델 하나, 엔드포인트 넷으로 끝나는 최소 API지만 토큰 인증 · 소유권 격리 · 멱등 확인 · 환경별 DB 전환이라는 핵심 안전장치가 빠짐없이 들어가 있다.
